# โปรแกรมที่ใช้ร่วมกับ Advisor

ในทางปฏิบัติ เราใช้ Obsidian เพื่ออ่านและเชื่อมโยงบันทึก ใช้ผู้ช่วย AI ทำงานกับแฟ้มโครงการ และเปิดเอกสารต้นฉบับด้วยโปรแกรมที่เหมาะกับชนิดไฟล์ ส่วนเครื่องมือค้นและถอดข้อความจะใช้เมื่อจำนวนเอกสารหรือลักษณะงานทำให้คุ้มกับการจัดเตรียม

## Obsidian สำหรับอ่านความรู้และตามที่มาของบันทึก

Obsidian เปิดโฟลเดอร์บันทึกบนเครื่องเป็นคลังที่เรียกว่า *vault* ได้ เราใช้คลังนี้คู่กับแฟ้มโครงการ โดยเก็บสำเนาข้อความจากต้นทางใน `raw/` และเขียนบันทึกที่เรียบเรียงแล้วใน `wiki/` เมื่อยกข้อสรุปมาใช้ ให้ทำลิงก์กลับไปยังต้นทางและระบุหน้าหรือช่องที่เกี่ยวข้อง สถานะงานปัจจุบันแก้ที่บันทึกหลักของโครงการ ส่วนหน้าในคลังความรู้ใช้ลิงก์ไปยังบันทึกหลักนั้น [คู่มือการเปิดโฟลเดอร์เป็น Vault](https://obsidian.md/help/vault)

ตัวอย่างเช่น ผู้เรียนอาจมีบันทึกเรื่อง “ค่าเฉลี่ยถ่วงน้ำหนัก” แล้วเชื่อมกับหน้าที่จดข้อผิดพลาดจากการทำโจทย์ เมื่อพบว่าคำอธิบายในบันทึกเดิมต้องแก้ ผู้เรียนเปิด *Backlinks* เพื่อดูว่าบันทึกใดอ้างถึงหน้านี้อยู่ และตามไปทบทวนตัวอย่างที่ได้รับผลด้วย วิธีเริ่มที่ง่ายคือเปิดโฟลเดอร์บันทึกส่วนตัวด้วยคำสั่ง *Open folder as vault* แล้วลองเชื่อมบันทึกสองหน้าที่ใช้ด้วยกัน [วิธีเชื่อมบันทึก](https://obsidian.md/help/links) · [คู่มือ Backlinks](https://obsidian.md/help/plugins/backlinks)

## ผู้ช่วย AI และโปรแกรมเอกสาร

| โปรแกรม | ใช้ทำอะไร | สิ่งที่เก็บไว้ให้ผู้รับช่วง |
|---|---|---|
| Codex และ Antigravity | อ่านข้อตกลงกับสถานะจากแฟ้มโครงการ ค้นหลักฐานที่เกี่ยวข้อง ช่วยจัดลำดับงานและทำร่าง | ผลงาน ตำแหน่งหลักฐาน และบันทึกงานถัดไป ผู้ช่วยอื่น เช่น Claude ที่ได้รับสิทธิ์อ่านแฟ้มเดียวกัน สามารถรับช่วงจากไฟล์เหล่านี้ได้ |
| Microsoft Word, Excel และโปรแกรมอ่าน PDF | เรียบเรียงงาน ตรวจสูตรและช่วงเซลล์ เทียบตารางหรือหน้าสแกนกับต้นฉบับ | ฉบับที่ใช้อ้าง พร้อมเลขหน้า หรือชื่อชีตและช่วงข้อมูล |
| Google Drive และ Google Sheets | รับไฟล์หรือทำงานบนตารางร่วมกับผู้ที่เกี่ยวข้อง เมื่อยอดยังเปลี่ยนได้ ให้เก็บสำเนาของรอบที่นำไปสรุป | วันที่ดึงข้อมูลและฉบับที่รองรับยอดนั้น เก็บไฟล์จริงในพื้นที่ที่จำกัดสิทธิ์ตามโครงการ |

## เครื่องมือสำหรับงานที่มีเอกสารจำนวนมาก

- **Python และ SQLite FTS5** ใช้ Python รวบรวมชื่อไฟล์ ตำแหน่ง และข้อความที่อ่านได้เข้าในดัชนี SQLite บนเครื่อง เมื่อค้นพบรายการ จึงเปิดหน้าเอกสารหรือแถวในตารางเพื่อตรวจคำตอบ สำหรับโครงการที่มีเอกสารไม่มาก เริ่มจากสารบัญ Markdown และการค้นในโฟลเดอร์ได้ [คู่มือ SQLite FTS5](https://www.sqlite.org/fts5.html)
- **MarkItDown** ใช้ทำสำเนาข้อความในรูป Markdown เพื่อค้นเนื้อหาจากเอกสารหลายชนิด การอ้างตาราง สูตร หรือเลขหน้ายังต้องกลับไปเปิดไฟล์ต้นทาง เพราะรูปแบบอาจเปลี่ยนระหว่างการแปลง [โครงการ MarkItDown](https://github.com/microsoft/markitdown)
- **Tesseract.js** ใช้อ่านตัวอักษรจากภาพ เมื่อเป็น PDF สแกน ให้แปลงหน้าที่ต้องการเป็นภาพก่อน แล้วเทียบผลกับภาพเดิม โดยเฉพาะวันที่ ตัวเลข และลายมือ [เอกสาร Tesseract.js](https://github.com/naptha/tesseract.js)
- **QMD** เป็นเครื่องมือค้นเสริมสำหรับคลังบันทึก ในงานที่ชื่อหัวข้อกับคำถามใช้คนละคำ อาจลองค้นเนื้อหาที่เกี่ยวข้องด้วย QMD แล้วเปิดเอกสารที่พบเพื่อตรวจว่าตอบคำถามได้จริง [โครงการ QMD](https://github.com/tobi/qmd)

## GitHub สำหรับแบ่งปันวิธีทำงาน

เราใช้ GitHub เก็บฉบับของคู่มือและแบบเปล่าที่ตั้งใจเผยแพร่ ผู้อ่านจึงเปิดดูได้ว่าหลักเกณฑ์หรือคำอธิบายเปลี่ยนอย่างไร แผนผังในหน้าแรกเขียนด้วย Mermaid และเก็บอยู่ในไฟล์เดียวกับคำอธิบาย จึงแก้ผังพร้อมกับขั้นตอนที่เปลี่ยนได้ [วิธีแสดงแผนผังใน GitHub](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)

ผู้ที่ต้องการลองใช้เริ่มจากแฟ้มส่วนตัว บันทึกสถานะหนึ่งหน้า และโปรแกรมที่เปิดเอกสารต้นทางได้ก่อน เมื่อพบปัญหา เช่น ต้องค้นข้อความเดิมซ้ำหลายครั้ง จึงค่อยเลือกเครื่องมือมาแก้ปัญหานั้น [แบบบันทึกสถานะ](../starter/current_state.md) · [กลับไปที่โครงร่างโครงการ](../README.md)
