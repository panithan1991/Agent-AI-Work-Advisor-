# โปรแกรมที่ใช้ร่วมกับ Advisor

ในทางปฏิบัติ เราใช้ Obsidian เพื่ออ่านและเชื่อมโยงบันทึก ใช้ผู้ช่วย AI ทำงานกับแฟ้มโครงการ และเปิดเอกสารต้นฉบับด้วยโปรแกรมที่เหมาะกับชนิดไฟล์ ส่วนเครื่องมือค้นและถอดข้อความจะใช้เมื่อจำนวนเอกสารหรือลักษณะงานทำให้คุ้มกับการจัดเตรียม

## Obsidian สำหรับอ่านความรู้และตามที่มาของบันทึก

Obsidian เปิดโฟลเดอร์บันทึกบนเครื่องเป็นคลังที่เรียกว่า *vault* ได้ เราใช้คลังนี้คู่กับแฟ้มโครงการ โดยเก็บสำเนาข้อความจากต้นทางใน `raw/` และเขียนบันทึกที่เรียบเรียงแล้วใน `wiki/` เมื่อยกข้อสรุปมาใช้ ให้ทำลิงก์กลับไปยังต้นทางและระบุหน้าหรือช่องที่เกี่ยวข้อง สถานะงานปัจจุบันแก้ที่บันทึกหลักของโครงการ ส่วนหน้าในคลังความรู้ใช้ลิงก์ไปยังบันทึกหลักนั้น [คู่มือการเปิดโฟลเดอร์เป็น Vault](https://obsidian.md/help/vault)

ตัวอย่างเช่น ผู้เรียนอาจมีบันทึกเรื่อง “ค่าเฉลี่ยถ่วงน้ำหนัก” แล้วเชื่อมกับหน้าที่จดข้อผิดพลาดจากการทำโจทย์ เมื่อพบว่าคำอธิบายในบันทึกเดิมต้องแก้ ผู้เรียนเปิด *Backlinks* เพื่อดูว่าบันทึกใดอ้างถึงหน้านี้อยู่ และตามไปทบทวนตัวอย่างที่ได้รับผลด้วย วิธีเริ่มที่ง่ายคือเปิดโฟลเดอร์บันทึกส่วนตัวด้วยคำสั่ง *Open folder as vault* แล้วลองเชื่อมบันทึกสองหน้าที่ใช้ด้วยกัน [วิธีเชื่อมบันทึก](https://obsidian.md/help/links) · [คู่มือ Backlinks](https://obsidian.md/help/plugins/backlinks)

## ผู้ช่วย AI และโปรแกรมเอกสาร

| โปรแกรม | ใช้ทำอะไร | สิ่งที่เก็บไว้ให้ผู้รับช่วง |
|---|---|---|
| Codex และ Antigravity | อ่านข้อตกลงกับสถานะจากแฟ้มโครงการ ค้นหลักฐานที่เกี่ยวข้อง ช่วยจัดลำดับงานและทำร่าง | ผลงาน ตำแหน่งหลักฐาน และบันทึกงานถัดไป ผู้ช่วยอื่น เช่น Claude ที่ได้รับสิทธิ์อ่านแฟ้มเดียวกัน สามารถรับช่วงจากไฟล์เหล่านี้ได้ |
| Microsoft Word, Excel และโปรแกรมอ่าน PDF | เรียบเรียงงาน ตรวจสูตรและช่วงเซลล์ เทียบตารางหรือหน้าสแกนกับต้นฉบับ | ฉบับที่ใช้อ้าง พร้อมเลขหน้า หรือชื่อชีตและช่วงข้อมูล |
| Google Drive และ Google Sheets | รับไฟล์หรือทำงานบนตารางร่วมกับผู้ที่เกี่ยวข้อง เมื่อยอดยังเปลี่ยนได้ ให้เก็บสำเนาของรอบที่นำไปสรุป | วันที่ดึงข้อมูลและฉบับที่รองรับยอดนั้น เก็บไฟล์จริงในพื้นที่ที่จำกัดสิทธิ์ตามโครงการ |

## โครงการบน GitHub ที่นำมาใช้ในงานจริง

ตารางนี้อธิบายว่าแต่ละโครงการช่วยงานขั้นใด ผู้อ่านเลือกใช้เฉพาะส่วนที่ตรงกับงานของตนได้ เช่น ผู้ที่อ่านเอกสารและจดสรุปด้วยตนเองเริ่มจากแบบบันทึกสถานะได้ทันที

| งาน | วิธีที่นำมาใช้ | โครงการต้นทาง |
|---|---|---|
| เขียนและเชื่อมบันทึกใน Obsidian | ใช้ชุดคู่มือสำหรับผู้ช่วย AI เช่น วิธีทำลิงก์ระหว่างบันทึก สร้างตารางจากข้อมูลกำกับบันทึก และจัดทำแผนภาพ Canvas | [Obsidian Skills](https://github.com/kepano/obsidian-skills) |
| เตรียมเอกสารสำหรับค้น | แปลงเอกสารเป็นสำเนาข้อความ Markdown เพื่ออ่านและค้นร่วมกัน เมื่อนำตาราง สูตร หรือตัวเลขไปอ้าง ให้อ้างกลับไปยังต้นฉบับ | [MarkItDown](https://github.com/microsoft/markitdown) |
| ค้นหลักฐานเพิ่มเติม | ค้นคำในดัชนี SQLite FTS5 บนเครื่องก่อน เมื่อคำที่ค้นต่างจากคำที่ผู้เขียนใช้และยังพบหลักฐานไม่พอ จึงใช้ QMD ช่วยหาเนื้อหาใกล้เคียง | [QMD](https://github.com/tobi/qmd) · [คู่มือ SQLite FTS5](https://www.sqlite.org/fts5.html) |
| อ่านเอกสารสแกน | ใช้ Tesseract.js อ่านตัวอักษรบนภาพ โดยใช้ข้อมูลภาษาจาก tessdata_fast สำหรับงานภาษาไทย แล้วเทียบวันที่ ตัวเลข และข้อความสำคัญกับภาพต้นฉบับ | [Tesseract.js](https://github.com/naptha/tesseract.js) · [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) |
| จัดทำ Word และตรวจ PDF | ใช้แบบ Word เดิมกรอกข้อมูลซ้ำ จัดย่อหน้าและตาราง และเปิดหน้าของ PDF เป็นภาพเพื่อตรวจสิ่งที่ผู้อ่านจะเห็น | [python-docx-template](https://github.com/elapouya/python-docx-template) · [python-docx](https://github.com/python-openxml/python-docx) · [PyMuPDF](https://github.com/pymupdf/PyMuPDF) |
| ถอดเสียงสำหรับทำบันทึก | ใช้กับงานที่มีเสียงประชุม เพื่อจัดทำร่างข้อความสำหรับทวนกับเสียงต้นฉบับก่อนนำข้อสรุปไปใช้ | [faster-whisper](https://github.com/SYSTRAN/faster-whisper) |
| อธิบายขั้นตอนให้ผู้อ่าน | เขียนแผนผังจากข้อความ เช่น แผนผังในหน้าแรก เมื่อขั้นตอนเปลี่ยนจึงแก้คู่มือกับแผนผังในไฟล์เดียวกันได้ | [Mermaid](https://github.com/mermaid-js/mermaid) |

## แนวคิดที่นำมาปรับใช้

- **LLM Wiki** เสนอวิธีแยกแหล่งข้อมูลออกจากบันทึกความรู้ที่เรียบเรียงแล้ว เรานำมาใช้โดยเก็บข้อความจากต้นทางใน `raw/` และเขียนคำอธิบายที่เชื่อมกลับไปหาหลักฐานใน `wiki/` เพื่อให้ปรับความรู้เดิมได้เมื่อมีข้อมูลใหม่ [ต้นฉบับ LLM Wiki บน GitHub Gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)
- **ReasoningBank** เป็นงานวิจัยเรื่องการเรียนรู้จากประสบการณ์ เราประยุกต์แนวคิดกับบันทึกบทเรียน โดยระบุว่าสถานการณ์เป็นอย่างไร ใช้วิธีใด เกิดผลอะไร และรอบต่อไปควรปรับตรงไหน [คำอธิบายงานวิจัยจาก Google Research](https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/)
- **Dream-RSI** เป็นแรงบันดาลใจให้เขียนเครื่องมือจำลองของโครงการเอง เพื่อทดลองว่าเมื่อจัดลำดับงานต่างกัน ผลจะเปลี่ยนอย่างไรภายใต้สมมติฐานเดียวกัน [โครงการวิจัย Dream-RSI](https://github.com/zhengkid/Dream-RSI)

## GitHub สำหรับแบ่งปันวิธีทำงาน

เราใช้ GitHub เก็บฉบับของคู่มือและแบบเปล่าที่ตั้งใจเผยแพร่ ผู้อ่านจึงเปิดดูได้ว่าหลักเกณฑ์หรือคำอธิบายเปลี่ยนอย่างไร GitHub แสดงแผนผังในหน้าแรกจากข้อความที่เก็บไว้กับคู่มือโดยตรง [วิธีแสดงแผนผังใน GitHub](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)

ผู้ที่ต้องการลองใช้เริ่มจากแฟ้มส่วนตัว บันทึกสถานะหนึ่งหน้า และโปรแกรมที่เปิดเอกสารต้นทางได้ก่อน เมื่อพบปัญหา เช่น ต้องค้นข้อความเดิมซ้ำหลายครั้ง จึงค่อยเลือกเครื่องมือมาแก้ปัญหานั้น [แบบบันทึกสถานะ](../starter/current_state.md) · [กลับไปที่โครงร่างโครงการ](../README.md)
